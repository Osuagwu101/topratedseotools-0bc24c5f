# Grammarly two-account routing

Account 1 retains the existing encrypted login, writer launches and document owners. Account 2 has an independent encrypted session. The legacy vault compatibility trigger mirrors only Account 1 and preserves rollback support. Existing document IDs remain globally unique and also have an account/document unique index; a collision across accounts fails closed.

Admin > Tools > Grammarly > Authorised session shows two account cards with save/replace, verify and revoke actions. Secret values are write-only. Super Admin alone manages provider sessions. Customer pages include the Grammarly account selector. Account 2 requires a saved session and a successful native authentication check before assignment. Each launch is bound to its account, and reassignment atomically revokes issued and active launches. No automatic fallback is provided.

HTTP requests select the bound account's cookies and CSRF token. Browser bearer headers are discarded. A dedicated transition page clears local/session storage, IndexedDB, Cache Storage and registered service workers before opening the provider page when the writer/account marker changes. Blocked database cleanup waits for other Grammarly tabs to close. Document queries, create records and checks include provider account. Database failures reject requests rather than return unfiltered document lists. Cookie rotation updates only its account and uses compare-and-swap against the request snapshot.

The live checking WebSocket relay also selects the assigned account. It verifies the site's origin, writer access, grant/order, provider status and document ownership. Every client frame rechecks access, and an idle connection is checked every two seconds. Revoked/reassigned sessions are closed. Binary collaboration frames are allowed only on a document-bound socket with verified ownership; unbound checking sockets require text frames. Authentication and document caches do not carry state between accounts.

Deploy the committed migration, build from this branch with the installed production dependency snapshot, then run scripts/grammarly-two-accounts/deploy.py from a clean checkout. The script starts a new main app on 3283, a Grammarly app on 3284 and checking relay on 3293, preserving each previous process's private environment and env-file arguments. It publishes hashed assets, verifies loopback health and tests Nginx before cutover. Legacy preview-cookie routing is removed from the enabled Grammarly vhost so both accounts use the account-aware authorization. Prior processes remain running for rollback.

Rollback restores the three vhosts from /home/ubuntu/deploy-backups/grammarly-two-accounts-20261116, validates and reloads Nginx. Keep additive database records, document owners and provider sessions. Do not delete customer or billing data.

Validation: existing Grammarly proxy/vault tests; tests/grammarly-two-accounts.test.ts; tests/grammarly-storage-reset.test.ts; tests/grammarly-two-accounts-ws.test.mjs with real downstream sockets and stubbed provider connections; server TypeScript; production build; schema preservation and transactional reassignment tests. scripts/grammarly-two-accounts/smoke.ts verifies a fresh authorized Account 1 launch and live checking handshake. Simultaneous live checks on two separate provider accounts remain pending until Account 2 is connected.
